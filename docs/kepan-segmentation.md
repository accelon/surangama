# 科判切刀：經文最小分段與段長統計

> 2026-11-05。資料為閱讀器目前載入的 `site/reader/kepan/kepan-data.js`（9 家科判、11,007 個節點，
> 2026-11-05 06:09 版；檔案 `note` 仍寫「六家」，實際 `editions` 有 9 個）與 `data/sutra.json`
> （3,732 句、66,014 漢字，含卷首序 46 句）。
>
> **後記（2026-11-05 再切分）**：`data/sentences.tsv` 已在 `：「`／`：『` 前再切（長句中的
> `『…』` 也加切，咒語按 `　` 切，`——` 也切），成為 4,890 句。
> 本文的 3,732 句與「句／段」分布是再切分前；2,418 個切點／段不變，漢字統計不變，
> 句數與中位數會變。新表見 [`sentence-index.md`](sentence-index.md)。

## 結論

**把 9 家科判所有節點的起點都當切刀、同一句只算一刀：2,418 個切點 → 2,418 段。**

這是一個很細的切法：1,607 段（66.5%）只有一句，95.4% 的段不超過三句。
而且 2,418 刀裡，子璿＋宣化兩家就佔 2,346 刀（97.0%），其餘七家合計只多 72 刀。

若只算有明確經文錨點的節點（子璿 1,196＋宣化 1,267），是 **1,637 個切點 → 1,638 段**。

「最少」的定義：所有切刀都必須保留時，能把相鄰句合併到的最大程度；不是 11,007 段，
也不是蒙鈔目錄的 27 段。

## 方法

- 切點＝每家科判每個節點的 `u`（主文句索引）；跨家聯集、去重。`u=0` 與卷末 `3732` 是固定邊界。
- 節點的 `off` 目前都是 0，所以切點只落在句界，沒有句內切分。
- 段長以「句」為主；另給「漢字」數（不計標點）。段內句數相加＝3,732，漢字相加＝66,014。
- 「只此一家」＝該切點不在其他任何一家的節點起點中。
- 實錨：子璿用 `changshui-sutra.json` 的經文對重算（1,196 條），宣化讀 `drba.json` 的 `exact=1`（1,267 條）。

## 觀察

1. **這組切刀不適合當閱讀單位。** 三分之二是單句段，95% 不超過三句；真正適合閱讀的
   可能是 lv≤5（121 段）或 750 錨點層（751 段）。
2. **九家不是九套獨立切點。** 11,007 個節點只有 2,418 個不同句位；科判樹的父節點與
   首個子節點常同句，且多數家的節點位置是表號內插，會大量疊在同一句。
3. **要「最少段」就必須取聯集。** 若為了減少段數而丟掉某一家的切點，就會違反「所有科判
   都保留」的前提；若要合併，應先決定只保留哪幾家、或只取哪幾層。
4. **卷首序的 37 句段**是全書最長句段（9–45）；若只看經文正分（46 起），段數少 3 段，
   即 2,415 段。

## 重跑

```powershell
bun run scripts/report-kepan-cuts.ts
```

產物：

- `build/kepan-cuts-summary.json`：全部統計與各家明細（建置產物，不進版控）。
- `data/kepan-segments.tsv`：2,418 段逐段明細（`n`、`u0`、`u1`、句數、漢字、卷、首句）。
- `data/sentences.tsv`：一行一句的句級定址主表，見 [`sentence-index.md`](sentence-index.md)。
- `data/sentence-kepan.tsv`：一行一節點的長表，主表的各家「起點數」在這裡展開。
